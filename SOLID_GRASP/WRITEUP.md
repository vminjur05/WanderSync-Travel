Single Responsibility Principle (Vignesh): The project class is responsible for managing the collection of tasks and team members. The task class manages things like status updates and priority handling. The TeamMember class focuses on team member behaviors like joining/leaving projects. By giving each class one reason to change, we reduce its complexity and make it follow the Single Responsibility Principle. 

Open/Closed Principle (Jyotir): We created a Task class that handles general task behaviors, and we also made RecurringTask and HighPriorityTask, each of which extends ITask. Task also extends ITask. This ensures that the new task types can be done without modifying the original Task class, making our code follow the Open/Closed Principle.

Liskov Substitution Principle (Abhiram): The RecurringTask and HighPriorityTask classes inherit from ITask and they can be used anywhere a Task is expected. Similarly, the ProjectManager can be used wherever  ITeamMember is needed. This system ensures that subclasses respect the interfaces of the base classes, showing that our classes adhere to the Liskov Substitution Principle. 

Interface Segregation Principle (Jude): The ITask interface handles the general task behaviors. Classes that need these capabilities, like HighPriorityTask and RecurringTask implement this interface. This ensures that the Task and TeamMember classes are not burdened with unneeded methods, which shows that our project follows the Interface Segregation Principle.

Dependency Inversion Principle (Andrew): We ensured that high-level modules do not depend on low-level modules, but instead interfaces. The ITask interface is inherited by the Task, HighPriorityTask and RecurringTask classes. The HighPriorityTask and RecurringTask classes could have extended the Task class, but we wanted to ensure that each type of task has its own logic that works in its given scenario, hence why our project follows the Dependency Inversion Principle.
